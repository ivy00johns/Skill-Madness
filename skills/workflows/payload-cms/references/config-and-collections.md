## 1. Project layout (Next.js app router)

> Verified against payload v3.90.2 (docs/admin/overview.mdx, docs/getting-started/installation.mdx, templates/blank/src, packages/next/package.json)

Payload lives inside the Next.js `app/` dir. Everything Payload owns sits in the `(payload)` route group; your site goes in a sibling group (name is arbitrary: `(frontend)`, `(app)`, `(my-app)`).

```text
src/
├─ app/
│  ├─ (payload)/
│  │  ├─ admin/[[...segments]]/page.tsx        # RootPage from @payloadcms/next/views
│  │  ├─ admin/[[...segments]]/not-found.tsx
│  │  ├─ admin/importMap.js                    # GENERATED - never hand-edit
│  │  ├─ api/[...slug]/route.ts                # REST_GET/POST/PATCH/PUT/DELETE/OPTIONS(config)
│  │  ├─ api/graphql/route.ts
│  │  ├─ api/graphql-playground/route.ts
│  │  ├─ custom.scss
│  │  └─ layout.tsx                            # RootLayout + handleServerFunctions
│  └─ (frontend)/                              # your site: layout.tsx owns <html>/<body>
├─ collections/  globals/  blocks/  ...
├─ payload.config.ts
└─ payload-types.ts                            # GENERATED by `payload generate:types`
```

- The `(payload)` files are boilerplate that "will never change" - copy them from `templates/blank/src/app/(payload)` when adding Payload to an existing app. Both route groups need their own root `layout.tsx` (Payload's owns `<html lang>` for the admin).
- Adding Payload to an existing Next app: move the existing root layout and pages into a new route group first, or the two root layouts collide.
- `tsconfig.json` must define the alias every generated file imports: `"paths": { "@payload-config": ["./src/payload.config.ts"], "@/*": ["./src/*"] }`.
- `next.config` must be ESM (`next.config.ts`/`.mjs` or `"type": "module"`) and wrapped: `export default withPayload(nextConfig, { devBundleServerPackages: false })` from `@payloadcms/next/withPayload`. `withPayload` warns if `experimental.staleTimes.dynamic` is non-zero (slows admin transitions) and on unsupported Next 16 versions.
- Blank template adds `images.localPatterns: [{ pathname: '/api/media/file/**' }]` so `next/image` can serve uploads from the Media collection; copy that for any `next/image` + local media setup.
- **Supported Next.js** (docs/getting-started/installation): `15.2.9`-`15.2.x`, `15.3.9`-`15.3.x`, `15.4.11`-`15.4.x`, `16.2.6`+. `packages/next/package.json` peerDependencies in the same tag say `>=16.3.3 <17.0.0` for 16 - a docs/peer-dep mismatch; when installing on Next 16, use 16.3.3+ to satisfy the peer range. Node `^18.20.2 || >=20.9.0` per package engines (docs say 20.9.0+). Yarn 1.x unsupported; npm may need `--legacy-peer-deps`.
- Packages: `payload @payloadcms/next` required; add `@payloadcms/richtext-lexical`, `sharp`, `graphql` (only if GraphQL used) and exactly one DB adapter (`@payloadcms/db-mongodb|db-postgres|db-sqlite`). Keep every `@payloadcms/*` package on the same exact version as `payload`.
- `v4:` Node minimum 24.15.0, Next minimum 16.2.6, TypeScript 6.0.3 (migration-guide/v4.mdx).

### Import map

> Verified against payload v3.90.2 (docs/custom-components/overview.mdx L145-190, packages/payload/src/config/types.ts L1003)

Custom admin components are referenced by string path in config (e.g. `'@/components/BeforeLogin'` or `'/components/X#Named'`), never imported. Payload writes `app/(payload)/admin/importMap.js` mapping every path to its import. It regenerates at startup and on HMR (`admin.importMap.autoGenerate`, default true). Run `pnpm payload generate:importmap` after adding/renaming a component path, in CI, and after plugin installs - a stale map is the usual cause of "component not found" admin errors. `admin.importMap.baseDir` resolves paths starting with `/` (default `process.cwd()`); template configs set it to `path.resolve(dirname)`. `importMapFile` overrides the file location.

## 2. Root config essentials (`buildConfig`)

> Verified against payload v3.90.2 (docs/configuration/overview.mdx, packages/payload/src/config/types.ts)

Required: `secret`, `db`. `collections` is required in practice. Minimal website-ready skeleton (matches `templates/website/src/payload.config.ts`):

```ts
import { mongooseAdapter } from '@payloadcms/db-mongodb'
import { lexicalEditor } from '@payloadcms/richtext-lexical'
import path from 'path'
import { buildConfig } from 'payload'
import sharp from 'sharp'
import { fileURLToPath } from 'url'

const filename = fileURLToPath(import.meta.url)
const dirname = path.dirname(filename)

export default buildConfig({
  admin: {
    user: Users.slug,                       // auth collection allowed into /admin
    importMap: { baseDir: path.resolve(dirname) },
    livePreview: { breakpoints: [{ label: 'Mobile', name: 'mobile', width: 375, height: 667 }] },
  },
  collections: [Pages, Posts, Media, Categories, Users],
  globals: [Header, Footer],
  editor: lexicalEditor(),
  db: mongooseAdapter({ url: process.env.DATABASE_URL || '' }),
  secret: process.env.PAYLOAD_SECRET || '',
  sharp,
  cors: [process.env.NEXT_PUBLIC_SERVER_URL].filter(Boolean) as string[],
  plugins: [],
  typescript: { outputFile: path.resolve(dirname, 'payload-types.ts') },
})
```

| Option | Notes |
| --- | --- |
| `secret` | Encryption/JWT signing secret. Rotating it invalidates sessions/tokens. |
| `db` | Adapter instance; see `deployment` reference for adapters, migrations, transactions. |
| `editor` | Default editor for `richText` fields. Per-field `editor` overrides. |
| `sharp` | Pass the imported module to enable resize/crop/focal point. Without it, `imageSizes` do nothing. |
| `serverURL` | Absolute origin only (`https://example.com`), no path. Also auto-added to the `csrf` whitelist. Leave unset for same-origin Next apps unless you need absolute URLs in emails/uploads. |
| `cors` | `'*'`, `string[]`, or `{ origins, headers }`. Needed only for cross-origin browser calls to the REST/GraphQL API. |
| `csrf` | Whitelist of origins allowed to send Payload's HTTP-only cookie. Add your frontend origin(s) if the frontend is on another domain. |
| `cookiePrefix` | Prefix for all Payload cookies (default `payload`); set per-site when several Payload apps share a parent domain. |
| `defaultDepth` / `maxDepth` | Default relationship depth (3.x default **2**); `maxDepth` caps client-requested depth (default 10). |
| `defaultMaxTextLength` | App-wide text length cap - useful on public-write collections. |
| `indexSortableFields` | Auto-index top-level sortable fields; needed for Azure Cosmos-style DBs. |
| `upload` | Global multipart options (see Upload section). |
| `routes` | Rebind admin/api/graphql root routes (also requires moving the `(payload)` folders). |
| `admin.user` | Slug of the auth collection that may log into `/admin`. Default provides a `users` collection. |
| `admin.livePreview` | Root-level Live Preview; collection/global `admin.livePreview` overrides merge over it. |
| `localization` | See section 8. |
| `folders` | `false` or `{ browseByFolder, slug ('payload-folders'), fieldName ('folder'), debug, collectionOverrides }`. Beta. |
| `graphQL` | `{ disable?, schemaOutputFile, ... }`; per-collection `graphQL: false` removes a collection from the schema. |
| `endpoints` | Root custom REST endpoints. |
| `onInit(payload)` | Runs after startup (seeding, dev bootstrap). |
| `experimental.localizeStatus` | Beta flag; required *in addition to* per-collection `versions.drafts.localizeStatus` (see section 4). |
| `compatibility.allowLocalizedWithinLocalized` | Only for pre-3.0 Mongo data. |
| `bin` | Custom `payload <key>` scripts (section 10). |
| `jobs`, `email`, `plugins`, `hooks`, `i18n`, `logger`, `telemetry: false`, `debug`, `cookiePrefix` | See other references. |

`typescript`: `{ outputFile, autoGenerate, declare, strictDraftTypes }`. `strictDraftTypes: true` types required fields optional when `draft: true` and forbids `draft` on collections without drafts - opt in now, it becomes default in v4. Generate types with `pnpm payload generate:types` (package.json script `generate:types`); types are stale until you do.

Config discovery for CLI (`payload ...`): cwd, then tsconfig `rootDir`/`outDir`, then `dist`. Override with `PAYLOAD_CONFIG_PATH` (absolute or cwd-relative).

`v4:` `bin` removed -> `cli: { commands: { seed: './seed.js#seedCommand' } }` using `defineCLICommand` from `payload/cli`; `defaultDepth` default drops to **1**; `typescript.generateInputTypes` added; `compatibility.allowLocalizedWithinLocalized` removed; storage adapters move from `plugins` to top-level `storage: []`; `generateTypes`/`generateImportMap` return result objects.

## 3. Collection options

> Verified against payload v3.90.2 (docs/configuration/collections.mdx, packages/payload/src/collections/config/types.ts L368-886)

```ts
import type { CollectionConfig } from 'payload'

export const Pages: CollectionConfig = {
  slug: 'pages',
  admin: {
    useAsTitle: 'title',
    defaultColumns: ['title', 'slug', 'updatedAt'],
    livePreview: { url: ({ data, req }) => `${req.protocol}//${req.host}/${data.slug === 'home' ? '' : data.slug}` },
    preview: (doc, { req }) => `${req.protocol}//${req.host}/next/preview?slug=${doc.slug}`,
  },
  defaultPopulate: { title: true, slug: true },   // what a *populated* Page contributes when referenced elsewhere
  access: { /* see access-and-hooks.md */ },
  versions: { drafts: { autosave: true, schedulePublish: true }, maxPerDoc: 50 },
  hooks: { /* ... */ },
  fields: [ /* ... */ ],
}
```

| Option | Notes |
| --- | --- |
| `slug` (required) | Also the API route (`/api/pages`) and DB table/collection name unless `dbName` set. |
| `fields` (required) | See `fields.md`. |
| `admin.useAsTitle` | Top-level field for titles. If it points at a relationship/join, only the ID displays - use a `virtual` field instead. |
| `admin.defaultColumns` | List-view columns. |
| `admin.preview` | `(doc, { locale, req, token }) => string \| null \| Promise`. Adds a Preview button. `doc` is the unsaved form data, so destructuring `({ slug })` works. |
| `admin.livePreview` | `{ url: string \| ({ data, collectionConfig, locale, req }) => string \| null, breakpoints, openByDefault }`. Return `null`/`undefined` to hide. Called often when autosave interval is small - keep it cheap. |
| `admin.group`, `hidden`, `description`, `listSearchableFields` | Index any `listSearchableFields`. |
| `admin.baseFilter` | Default filter for list view and Lexical internal-link pickers (used by multi-tenant). |
| `admin.folders` / `folders: true` | Enable folder grouping (beta). |
| `defaultPopulate` | Select applied whenever this collection is populated from another doc; big win for `pages` referenced by nav/CTA links (`{ slug: true, title: true }`). |
| `forceSelect` | Fields always selected regardless of caller `select` (needed by hooks/access). `v4:` removed for a `select` function on the collection. |
| `indexes` | `[{ fields: ['tenant', 'slug'], unique: true }]` compound indexes. |
| `defaultSort` | `'-createdAt'` or array. |
| `orderable` | Fractional-index drag-reorder; helpers `generateKeyBetween`, `generateNKeysBetween` from `payload/shared`. |
| `timestamps` | `false` to drop `createdAt`/`updatedAt`. |
| `disableDuplicate`, `disableBulkEdit`, `disableBulkDelete` | Lock down list actions. |
| `lockDocuments` | On by default (edit-lock indicator); `false` or `{ duration }`. |
| `trash: true` | Soft delete (section 10). |
| `endpoints` | Custom REST routes; `false` disables built-ins. |
| `graphQL` | `false`, or `{ singularName, pluralName, disableQueries, disableMutations }`. |
| `typescript.interface` | Override generated interface name. |
| `custom` | Free-form extension data for plugins. |

`v4:` collections gain `hierarchy` (tree + generated paths); `admin.enableListViewSelectAPI` removed (now always on); `admin.hideAPIURL` removed; versions default **on** (`versions: true`, maxPerDoc 100) for every non-auth collection - set `versions: false` explicitly to opt out (docs/migration-guide/v4.mdx).

## 4. Versions, drafts, autosave, scheduled publish

> Verified against payload v3.90.2 (docs/versions/{overview,drafts,autosave}.mdx, packages/payload/src/versions/types.ts)

- `versions: true` (3.x: opt in) creates `_{slug}_versions` (full doc copy + `parent`, `autosave` flag). `maxPerDoc` default 100, `0` keeps all. Globals use `max`.
- `versions.drafts` (true or object) injects a `_status: 'draft' | 'published'` field. Options: `autosave` (true or `{ interval = 800, showSaveDraftButton = false }`), `schedulePublish` (true or object), `validate` (validate drafts on save; default false), `localizeStatus` (beta).
- `draft` API param: controls **validation** (required fields skipped) and **write location**. On update `draft: true` writes *only* to the versions table; the main doc keeps the published content. Publishing = set `_status: 'published'` explicitly (overrides `draft: true`). First create always writes the main doc, default `_status: 'draft'`. `_status: 'draft'` alone does not bypass `required`; pass `draft: true`.
- Reading: `find`/`findByID` with `draft: true` return the *latest version* (draft or published), not the main doc. **`draft: true` does not filter by status** - protect drafts with `read` access, e.g. return `{ _status: { equals: 'published' } }` for anonymous users. If drafts were added to a collection that already had docs, old docs have no `_status` until re-saved: allow `{ or: [{ _status: { equals: 'published' } }, { _status: { exists: false } }] }`.
- Publish permission: return a `_status` constraint from `update` access (`{ _status: { equals: 'draft' } }` for editors) - the admin hides Publish/Unpublish when the constraint blocks it, and it also blocks scheduled-publish jobs for those users.
- `schedulePublish` works by queueing a Job; **nothing publishes unless jobs are being run** (Vercel Cron -> `/api/payload-jobs/run`, `autoRun`, or `payload jobs:run`). The website template wires `jobs.access.run` to a `CRON_SECRET` bearer for this reason.
- Localized status: needs `experimental: { localizeStatus: true }` in root config **and** `versions.drafts.localizeStatus: true` on the collection/global (sanitize forces it back to false without the root flag - `globals/config/sanitize.ts` L121-127). `_status` then becomes `{ en: 'published', es: 'draft' }`.
- Version REST: `GET /api/{slug}/versions`, `GET|POST /api/{slug}/versions/:id` (POST restores). Local: `findVersions`, `findVersionByID`, `restoreVersion`, `countVersions`.
- `v4:` version reads inherit the collection `read` access when `readVersions` is unset (a public `read` makes drafts/history public); set `access.readVersions` explicitly.

## 5. Globals

> Verified against payload v3.90.2 (docs/configuration/globals.mdx)

Single-document collections (header nav, footer, site settings). Options mirror collections: `slug`, `fields`, `access` (`read`, `update`, `readVersions`, ...), `hooks`, `versions` (`{ max, drafts }`), `admin` (`group`, `hidden`, `livePreview`, `preview`, `components`), `label`, `dbName`, `endpoints`, `graphQL`, `lockDocuments`.

```ts
export const Header: GlobalConfig = {
  slug: 'header',
  access: { read: () => true },
  fields: [{ name: 'navItems', type: 'array', maxRows: 6, fields: [linkField] }],
  hooks: { afterChange: [revalidateHeader] },
}
```

Read with `payload.findGlobal({ slug: 'header', depth: 1 })`; write with `updateGlobal`. Globals are the right home for nav/footer/banner/SEO defaults; use a collection when more than one doc shares the shape.

## 6. Upload collections

> Verified against payload v3.90.2 (docs/upload/overview.mdx, packages/payload/src/uploads/fetchAPI-multipart/index.ts L8-30)

```ts
export const Media: CollectionConfig = {
  slug: 'media',
  access: { read: () => true },              // public site needs public read
  upload: {
    staticDir: 'media',                       // local disk; irrelevant with a cloud storage adapter
    imageSizes: [{ name: 'thumbnail', width: 400, height: 300, position: 'centre' }, { name: 'tablet', width: 1024, height: undefined }],
    adminThumbnail: 'thumbnail',
    mimeTypes: ['image/*'],
  },
  fields: [{ name: 'alt', type: 'text', required: true }],
}
```

- Auto-adds `filename`, `mimeType`, `filesize`, `url`, `thumbnailURL`, `width`, `height`, `focalX/Y`, and `sizes.{name}` when `imageSizes` set. Files are served at `/api/{slug}/file/{filename}` by default.
- Other options: `crop`, `focalPoint`, `disableLocalStorage` (required with serverless/cloud storage), `pasteURL`, `filesRequiredOnCreate`, `bulkUpload`, `formatOptions`, `resizeOptions`, `withMetadata`, `handlers`, `modifyResponseHeaders`, `allowRestrictedFileTypes`.
- **Default multipart limits** (source, `DEFAULT_UPLOAD_OPTIONS`): 20 MiB per file, **3 files per request**, 20 non-file fields, 1 MiB per field, 50 MiB request total, `abortOnLimit: true` (413 on overflow), 60 s timeout. Raise via root `upload: { limits: { fileSize, files }, requestSizeLimit }`. Seeding scripts that upload through the REST API hit `files: 3`; the Local API `create` with `filePath`/`file` does not go through multipart.
- Files on serverless hosts (Vercel/Cloudflare) need a storage adapter (`@payloadcms/storage-vercel-blob|s3|r2|gcs|azure`) - local `staticDir` disk is ephemeral. `v4:` adapters must be under top-level `storage`, not `plugins`.

## 7. Auth collections

> Verified against payload v3.90.2 (docs/authentication/{overview,operations,cookies}.mdx, packages/payload/src/collections/config/defaults.ts L131-148)

`auth: true` or an options object. Admin editors typically live in `users` (`admin.user: 'users'`); site members/customers in a separate collection so they cannot enter `/admin`.

Options: `tokenExpiration` (seconds, default 7200), `verify` (email verification), `maxLoginAttempts` + `lockTime` (ms), `useAPIKey`, `loginWithUsername` (`true` or `{ allowEmailLogin, requireEmail }`), `cookies` (`{ secure, sameSite, domain }`), `depth` (populate depth for `req.user`, default 0), `forgotPassword`, `strategies`, `disableLocalStrategy`, `removeTokenFromResponses`, `useSessions` (**default true**; `false` = stateless JWT that cannot be revoked).

- Sessions on: logout ends only the presenting session (`allSessions: true` ends all). Changing a password ends the user's *other* sessions; a Local API `update` of a password with no `user` passed ends **all** of that user's sessions, so pass the `user` from `payload.auth({ headers })` when the requester should stay logged in.
- Fields on `req.user` are limited to what is in the JWT plus `depth`; mark role fields `saveToJWT: true` to read them in access functions without a DB lookup.
- Cross-domain cookies need `csrf` whitelist plus `cookies: { sameSite: 'None', secure: true }` (or serve API on a subdomain).
- Server components: `const { user } = await payload.auth({ headers: await headers() })` (from `next/headers`).
- `v4:` JWTs carry a signed-header `authVersion: 1`; unpatched pre-fix tokens are rejected (users re-login); reserved `saveToJWT` aliases (`id`, `collection`, `email`, `sid`, `iat`, `exp`) are ignored.

## 8. Localization

> Verified against payload v3.90.2 (docs/configuration/localization.mdx)

```ts
localization: {
  locales: [{ code: 'en', label: 'English' }, { code: 'ar', label: 'Arabic', rtl: true }, { code: 'es', label: 'Spanish', fallbackLocale: 'en' }],
  defaultLocale: 'en',   // required
  fallback: true,        // default true: missing localized values fall back to the fallback locale
  filterAvailableLocales: async ({ req, locales }) => locales,
}
```

- Per **field**: `localized: true` (any named field type, including blocks/arrays). Stored as `{ en: ..., es: ... }`. Nested `localized` inside a localized parent is dropped by sanitize.
- Toggling `localized` on a field with data loses that data - plan a migration first.
- Reads: REST `?locale=es&fallback-locale=none` (`'null'|'false'|'none'` disable fallback); Local API `locale: 'es'`, `fallbackLocale: false`; `locale: 'all'` returns every locale. GraphQL `locale`/`fallbackLocale` args (enum-formatted).
- `v4:` `localization.defaultLocalePublishOption` removed; admin Publish defaults to the active locale.

## 9. Preview vs Live Preview

> Verified against payload v3.90.2 (docs/admin/preview.mdx, docs/live-preview/overview.mdx, packages/payload/src/config/types.ts L171-201, L261)

- **Preview** (`admin.preview`) = button linking to your frontend. Draft Preview in Next: point it at a route handler (e.g. `/next/preview?slug=...&collection=...&path=...&previewSecret=...`) that checks the secret, authenticates via `payload.auth`, calls `draftMode().enable()`, and redirects; pages then query with `draft: draftMode().isEnabled`.
- **Live Preview** (`admin.livePreview`) = iframe of your frontend with `postMessage` updates while typing. Config `{ url, breakpoints, collections, globals, openByDefault }` at root, or per collection/global (merged). The frontend must render with `@payloadcms/live-preview-react` (`useLivePreview` client-side, or the server-side `RefreshRouteOnSave` pattern used by the website template).
- Both `url`/`preview` may be relative; Payload prepends the browser origin. Use `req.protocol`/`req.host` for Vercel preview deployments.

## 10. Custom endpoints, folders, trash, bin scripts

> Verified against payload v3.90.2 (docs/rest-api/overview.mdx L577+, docs/folders/overview.mdx, docs/trash/overview.mdx, docs/configuration/overview.mdx)

- **Endpoints**: `endpoints: [{ path: '/:id/tracking', method: 'get', handler: async (req) => Response.json(...) }]` on root (`/api/...`), a collection (`/api/{slug}/...`) or a global. Handler gets `PayloadRequest` (`req.user`, `req.payload`, `req.routeParams`, `req.json()`). **Not authenticated by default** - check `req.user` yourself. Lowercase methods.
- **Trash**: `trash: true` adds `deletedAt`; deletes soft-delete by default; `find({ trash: true })` includes trashed docs, plus `where: { deletedAt: { exists: true } }` for trashed-only; admin gets `/collections/:slug/trash`. Supported on find/findByID/update/delete/findVersions.
- **Folders** (beta): root `folders: {...}` + collection `folders: true`; adds a hidden `folder` relationship and a `payload-folders` collection.
- **Bin scripts** (3.x): `bin: [{ key: 'seed', scriptPath: path.resolve(dirname, 'seed.ts') }]`; the script must `export const script = async (config) => { await payload.init({ config }); ...; process.exit(0) }`; run `pnpm payload seed`. Any bin script accepts `--cron "0 * * * *"`. `pnpm payload run ./script.ts` runs an arbitrary script with Payload initialized.
