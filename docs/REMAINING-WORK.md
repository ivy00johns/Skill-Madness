### 2026-07-21 — pxpipe adoption (`PX`)

pxpipe (`teamchong/pxpipe`, MIT, v0.8.0, ~8 weeks old) is a local proxy for Claude Code that renders the bulky re-sent parts of every request (system prompt, tool docs, older history) into dense PNG images — image tokens are priced by pixel area, not characters — cutting the measured input-token bill **~59–70%** on real Claude Code traffic while preserving the prompt cache. The dive's verdict, adopted here: wire it as an opt-in skill parallel to `use-freellmapi` — proxy the harness, fork nothing, never vendor. The embed-the-render-API idea is parked as PX-4 in [`docs/FUTURE.md`](FUTURE.md).

- **PX-1** `[open · P1]` — **Build `use-pxpipe`: opt-in token-saver proxy wiring skill.** After running one skill, Claude Code sessions cost roughly half to a third as much in input tokens; a local dashboard shows the live savings, and one command turns it all off. The skill wires `ANTHROPIC_BASE_URL` behind a one-line-reversible toggle, verifies compression fired AND the prompt cache stayed warm (a mis-set boundary historically produced a −250% regression), carries the loopback-only security posture, and hands off with the "imaged bulk is gist-only — never the sole copy of secrets/hashes" caveat. Direct analog of `use-freellmapi`, one level up (harness, not app). Honest caveat: upstream is 8 weeks old at v0.8.x — wired opt-in, never vendored. Note: a new skill ripples the catalog count (README table/diagram, plugin.json) — same build-session discipline as CB-3. Source: `[PX]`.
- **PX-2** `[open · P2]` — **`madness` front-door proxy suggestion.** When a big multi-agent build or loop starts through `madness`, the front door asks once "enable the token-saver proxy for this run?" — and knows when *not* to ask (byte-exact-critical or short sessions). Suggest-only, never auto-enable. Depends on PX-1. Source: `[PX]`.
- **PX-3** `[open · P2]` — **Model-safety allowlist for the image proxy lives in `model-adaptation`.** One governed place says which models may safely sit behind the image proxy — pxpipe measured Opus 4.8 reading dense hex 6/15 vs Fable 5's 13–15/15, and imaging a model that misreads produces confident wrong answers — re-verified per model release via pxpipe's cheap ~20-call glyph sweep. Dovetails with MA-2's optimizer/target tiering section (same file). The load-bearing safety rule for the whole adoption. Source: `[PX]`.

Observable change: one right skill fires instead of several plausible ones, and "no skill" becomes a legal outcome. Source: `[HE]`.
